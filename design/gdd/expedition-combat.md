## Summary

영지 던전 입구(`DungeonPopup`)에서 항상 원정 준비 화면(`expedition_prep.gd`)을 경유해 파티 인원(최대 5명)과 전열·중열·후열 배치를 확인하고, 5명 미만 시 확인 팝업을 거쳐 일반 원정 또는 심층 보스 봉인 원정에 출진하는 시스템이다. 전투(`dungeon.gd`)는 아군 3×3(9칸) vs 적군 3×3(9칸) 그리드 필드에서 3개 회랑 연속 돌파로 진행되며, 결과 화면(`dungeon_result.gd`)은 던전 도중 전사한 캐릭터를 최상단 붉은 강조 섹션으로 분리 표시하고 6단계 일일 정산(`return_to_estate()`)으로 영지에 복귀한다.

## Overview

**원정 준비 · 3×3 전투 진형 · 결과 정산 시스템(Expedition & 3×3 Combat)**은 영지 운영과 던전 전투 사이의 전환 관문 및 턴제 전투 구도를 담당한다. 실수로 편성이 부족하거나 배치를 확인하지 않은 채 출진하는 사고를 막기 위해 `DungeonPopup`의 즉시 출진을 금지하고 모든 출진을 `expedition_prep.gd`로 단일화하며, 5명 미만 편성 출발 시 확인 팝업을 띄운다. 전투 필드는 기존 횡 1열 구도에서 전열 3 · 중열 3 · 후열 3(총 9칸) 3×3 진형으로 배치되며, 원정 종료 후 클리어 여부와 무관하게 던전 도중 전사한 용병과 유품 생성 여부를 결과 화면에서 즉시 확인할 수 있게 한다.

## Player Fantasy

플레이어는 출진 전 전열·중열·후열 진형을 점검하는 지휘관으로서의 통제감을 느끼고, 9칸 전술 그리드 위에서 각 위치에 선 용병들이 어둠의 균열 괴수들과 맞서는 클래식 턴제 RPG의 현장감을 체감한다. 원정 후에는 승리했더라도 누가 쓰러져 유품을 남겼는지 직관적으로 마주하며 영지의 도덕적 결단 루프로 이어진다.

## Detailed Design

### Core Rules

1. **원정 출진 단일 관문 (`DungeonPopup` → `expedition_prep.gd` → `GameState.start_expedition(boss_mode)`):**
   - `DungeonPopup`(`dungeon_popup.gd`)에는 즉시 던전 진입 버튼이 없으며 `[⚔️ 원정 준비 화면으로 이동 ↗]`만 제공한다.
   - `expedition_prep.gd`는 전열(`FRONT=0`)·중열(`MID=1`)·후열(`BACK=2`) 3열 × 열당 최대 `ROW_SLOTS(3)`칸(파티 최대 `MAX_PARTY = 5`명)으로 진형을 편성한다. 용병은 생성 시 부여된 자신의 `row` 열에만 편성 가능하다.
   - 하단에 `[던전 입장 ↗]`(일반)과 `[👑 심층 보스 입장 ↗]`(`can_enter_boss_expedition()` 해금 시 활성) 두 출진 버튼을 제공한다.
2. **5명 미만 편성 출발 확인 팝업 (`expedition_prep.gd:_request_enter()`):**
   - `GameState.party.size() < GameState.MAX_PARTY(5)`인 상태에서 입장 버튼을 누르면 즉시 출진하지 않고 확인 모달을 표시한다:
     - 헤더: `⚠ 안내` + `[✕]` 닫기 버튼
     - 본문: `"인원이 5명 미만입니다. (현재 N / 5명)\n이대로 출발하시겠습니까?"`
     - 버튼: `[취소]`(기본 포커스) / `[출발]` (`ESC` 키·배경 딤 클릭으로 닫기 지원)
   - 파티가 5명 모두 편성된 경우 확인 팝업 없이 즉시 `GameState.start_expedition(boss_mode)` → `SCENE_DUNGEON`으로 진입한다.
3. **3×3 (전열 3 · 중열 3 · 후열 3 = 9칸) 전투 필드 (`dungeon.gd`):**
   - 현재 3×3 그리드는 **시각적 진형 배치**를 구현한다(전열/중열/후열별 사거리·타겟팅 제한은 미구현 — 추후 확장 가능).
   - **아군 9칸 (좌측 3×3):** `ALLY_GRID_COL_X = [440.0, 300.0, 160.0]` (`FRONT=0, MID=1, BACK=2`), `GRID_SLOT_Y = [132.0, 178.0, 224.0]` (석조 바닥 상/중/하 3슬롯, 원근 오프셋 `±14px`), `scale = Vector2(0.84, 0.84)`, `z_index = slot_idx`.
   - **적군 9칸 (우측 3×3):** `ENEMY_GRID_COL_X = [740.0, 880.0, 1020.0]` (적 전열/중열/후열), 몬스터 수별 입체 진형(`1체: (0,1)`, `2체: (0,1),(1,1)`, `3체: (0,0),(0,2),(1,1)`). *(배경 위 사각형 격자선은 그리지 않고 캐릭터 배치만으로 3×3 진형을 표현한다.)*
4. **3회랑 진행 및 사망 HP 최종 동기화 (`dungeon.gd`):**
   - 1~3회랑 연속 돌파(갈림길 선택 → 전투/이벤트/상점 → 3회랑 보스).
   - `_end(outcome)` 실행 시 `GameState.finalize_expedition()` 호출 직전에 모든 `_party_units`의 `u.merc_data.hp = 0 if u.is_dead else maxi(0, u.current_hp)`를 최종 동기화해 사망자 누락을 방지한다.
5. **결과 화면 전사자 명시 및 엔딩/귀환 연동 (`dungeon_result.gd`):**
   - `_build_party(r)` 상단에 `생존 N` / `전사 M` / `실종 K` 칩 요약을 표시한다.
   - `r.dead`가 비어 있지 않으면 클리어 여부와 무관하게 최상단에 붉은 강조 섹션(`☠ 던전 도중 전사 (M명) — 이름(직업 Lv.X)` + `전사 (유품 생성)` 배지)을 분리 표시한다. 전사자가 없으면 `"✦ 전사자 없음"` 안내를 표시한다.
   - `_build_ripple(r)`는 `GameState.preview_return_settlement(r, false)` 공용 프리뷰로 항목별 파문과 신규 유품 생성 수를 표시한다.
   - 심층 보스 봉인 성공(`not GameState.pending_ending.is_empty()`) 시 속죄/폭군 엔딩 오버레이를 표시한 뒤 `[연대기 계속하기]`로 엔드리스 사이클을 증가시킨다.
   - `[영지로 귀환 ↗]` 클릭 시 `GameState.return_to_estate()` 후 `not pending_succession_summary.is_empty()`이면 `SCENE_GAMEOVER`(세대 교체 결산), 아니면 `SCENE_ESTATE`로 전환한다.

### States and Transitions

| 상태 (State) | 설명 | 허용 전이 |
|---|---|---|
| `ESTATE_DUNGEON_POPUP` | 영지 던전 입구 팝업 (`dungeon_popup.gd`) | → `EXPEDITION_PREP` (`원정 준비 화면으로 이동`) |
| `EXPEDITION_PREP` | 진형 편성 및 5명 미만 확인 (`expedition_prep.gd`) | → `DUNGEON_MAP` (`start_expedition(boss_mode)`) / → `ESTATE` (뒤로) |
| `DUNGEON_MAP` / `DUNGEON_BATTLE` | 3회랑 갈림길 및 3×3 턴제 전투 (`dungeon.gd`) | → `DUNGEON_RESULT` (`clear` / `retreat` / `wipe`) |
| `DUNGEON_RESULT` | 전사자·전리품·파문·엔딩 정산 (`dungeon_result.gd`) | → `SCENE_ESTATE` (생존) / → `SCENE_GAMEOVER` (몰락·세대 교체) |

## Formulas

### 1. 원정 기본 골드 (`_base_gold`)
`_base_gold = 120 + dungeon_activity + randi_range(0, 60)` (+ 회랑 전진 시 `+ 60 * current_stage`)

### 2. 회랑 몬스터 스탯 스케일링 (`generate_monsters` / `generate_stage_monsters`)
- `tier_mult = 1.0 + monster_tier * 0.25`
- `act_mult = 1.0 + dungeon_activity / 100.0`
- `endless_mult = 1.0 + endless_cycle * 0.20`
- `stage_mult = 1.0 + (stage - 1) * 0.22`
- 심층 보스전 최종 회랑(`is_boss_expedition and stage >= max_stage`): 보스 `HP × 2.2`, `ATK × 1.45`

### 3. 전투 피해 파이프라인 (`DamagePipeline`)
`BaseDamage(dmin..dmax) → +party_attack_bonus(대장간+원정축복) → ×multiplier → ×crit_mult(아군 1.5x / 적군 1.4x, crit_pct = clampf(base+skill+party_crit_bonus, 0, 100)) → ×(1 - prot_pct/100)` (최소 피해 `1`)

| 파라미터 | 기본값 | 위치 | 조정 시 체감 영향 |

| 보스 배율 (`HP / ATK`) | `2.2x / 1.45x` | `game_state.gd` | 심층 보스 최종 회랑 난이도 |

## Edge Cases

- **If `GameState.party.is_empty()`인 상태에서 출진을 시도하면**: 입장 버튼이 비활성화되며 `start_expedition()`도 `false`를 반환한다.
- **If `GameState.last_result.is_empty()`인 상태로 `dungeon_result.tscn`에 직접 진입하면**: `_ready()`에서 `change_scene_to_file.call_deferred(SCENE_ESTATE)`로 안전 복귀한다.
- **If 전투 중 용병이 사망했으나 파티가 클리어하면**: `_end("clear")` 직전 `merc_data.hp = 0` 최종 동기화로 `r.dead`에 정확히 집계되며, 결과 화면 최상단 `☠ 던전 도중 전사` 섹션에 표시되고 영지 귀환 시 `UNRESOLVED` 유품이 생성된다.
- **If 5명 미만 확인 팝업에서 `ESC` 또는 배경 딤을 클릭하면**: 팝업만 닫히고 원정 준비 화면이 유지된다.

## Acceptance Criteria

- **AC-1 (단일 출진 관문):** `DungeonPopup`에는 즉시 출진 버튼이 없고 `[원정 준비 화면으로 이동]`만 존재하며, 일반/심층 보스 출진은 모두 `expedition_prep.gd`에서 수행된다.
- **AC-2 (5명 미만 확인 팝업):** `party.size()`가 `1~4`일 때 입장 버튼 클릭 시 확인 팝업이 열리고 `[취소]`/`ESC`로 취소, `[출발]`로 출진한다. `party.size() == 5`일 때는 팝업 없이 즉시 출진한다.
- **AC-3 (3×3 9칸 전투 진형):** `dungeon.gd` 진입 시 `FormationGridCanvas`가 아군/적군 각 9칸 타일을 렌더링하고, 각 아군 유닛이 자신의 `row` 및 열 내 슬롯 인덱스에 맞는 `(ALLY_GRID_COL_X[row], GRID_SLOT_Y[slot])` 좌표에 배치된다.
- **AC-4 (클리어 화면 전사자 명시):** 원정 클리어 시 `r.dead`에 1명 이상이 포함되면 `dungeon_result.gd`의 파티 현황 최상단에 `☠ 던전 도중 전사` 섹션과 `전사 (유품 생성)` 배지가 표시된다.
