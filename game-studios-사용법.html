1단계 · 컨셉 (Concept)

/brainstorm→/design-review→/setup-engine→/prototype→/map-systems→/art-bible→/gate-check
스킬용도산출물
/brainstorm컨셉 후보 10개, MDA·플레이어 동기 분석 후 선택design/gdd/game-concept.md
/design-review컨셉 문서의 완결성·일관성 검증리뷰 결과
/setup-engine엔진·버전 고정 (이 프로젝트: Godot 4.6.x)project.yaml
/prototype브라우저/엔진 프로토타입 후 PROCEED·PIVOT·KILL 결정프로토타입 폴더
/map-systems시스템 분해, 의존성, 설계 우선순위design/gdd/systems-index.md
/art-bible시각 정체성(색·형태·분위기) 확정. 에셋 제작 전 필수아트 바이블

2단계 · 시스템 설계 (Systems Design)

/design-system→/design-review→/quick-design→/review-all-gdds→/consistency-check→/gate-check
스킬용도
/design-system <시스템>시스템 하나의 GDD를 섹션별로 함께 작성. 의존 문서 교차 참조
/design-review <파일>GDD 한 건 검수(완결성·구현 가능성)
/quick-design튜닝·소규모 기능용 경량 스펙 (전체 GDD 생략)
/review-all-gdds전 GDD 교차 검토: 모순, 지배 전략, 경제 불균형, 필러 이탈
/consistency-check엔티티 레지스트리와 GDD 간 수치·용어 충돌 탐지
/balance-check공식·데이터의 밸런스 이상치 탐지

3단계 · 기술 설정 (Technical Setup)

/create-architecture→/architecture-decision→/architecture-review→/create-control-manifest→/ux-design(접근성)→/test-setup→/gate-check
스킬용도
/create-architecture코드 작성 전 아키텍처 청사진. 엔진 지식 공백 표시
/architecture-decisionADR 작성 (맥락, 대안, 결과)
/architecture-reviewGDD 요구 ↔ ADR 추적 매트릭스, ADR 간 충돌 검사
/create-control-manifestADR에서 "해야 할 것/하지 말 것" 코딩 규칙 요약 생성
/test-setuptests/, 엔진 러너, CI 워크플로 구성
/test-helpers엔진별 테스트 헬퍼(어서션, 팩토리, 목) 생성

4단계 · 프리프로덕션 (Pre-Production)

/ux-design→/ux-review→/vertical-slice→/create-epics→/create-stories→/story-readiness→/estimate→/sprint-plan→/gate-check
스킬용도
/ux-design화면·플로우·HUD UX 스펙 작성
/ux-reviewUX 스펙 검증: APPROVED / NEEDS REVISION 등
/vertical-slice전체 루프가 가능한지 확인하는 종단 간 빌드
/create-epicsGDD+아키텍처를 모듈별 에픽으로 분해
/create-stories <에픽>에픽 하나를 인수 기준 포함 스토리로 분해
/story-readiness스토리가 구현 착수 가능한지(인수 기준, ADR, 의존성) 점검
/estimate복잡도·리스크 기반 공수 추정
/sprint-plan스프린트 계획 작성/갱신

5단계 · 프로덕션 (Production) — 스프린트 반복

/story-readiness→/dev-story→/code-review→/story-done→/sprint-status→/retrospective
스킬용도
/dev-story스토리 1건을 ADR 준수·테스트와 함께 구현
/code-review코딩 표준, SOLID, 테스트 용이성, 성능 리뷰
/story-done인수 기준 검증 후 스토리 종료, 상태 갱신
/sprint-status번다운·리스크 스냅샷
/content-auditGDD 계획 수량 대비 구현 수량 감사
/propagate-design-changeGDD 변경으로 낡은 ADR 탐지 및 정리
/scope-check · /milestone-review범위 이탈 점검 / 마일스톤 go·no-go
/bug-report · /bug-triage버그 보고서 작성 / 우선순위·스프린트 배정
/hotfix긴급 수정 (브랜치, 승인, 백포트 검증)
구현 전 흐름: /story-readiness → /dev-story → /story-done 순서를 지키면 인수 기준·ADR 위반이 중간에 잡힙니다.

팁과 프로젝트 규칙

  • 단계 전환 전에는 항상 /gate-check로 판정을 받으세요. FAIL이면 부족한 산출물이 표시됩니다.
  • 막히면 /next-step, 진행 상황이 궁금하면 /project-stage-detect.
  • 작업이 끝나면 .docs/YYYY-MM-DD_HHMM_<주제>_report.md 보고서를 남깁니다.
  • 변경 이력 확인: /write-changelog (구 /changelog), 설정 확인: /project-settings (구 /settings).
  • 스킬 최신화: 원본 저장소와 비교해 병합합니다. 백업은 .tools/.test/skills_backup_20261123.
  • 엔진 레퍼런스(docs/engine-reference/godot/)로 폐기된 API를 확인하며 Godot 4.x 표준을 지킵니다.
